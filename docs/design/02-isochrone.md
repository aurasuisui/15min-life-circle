## 1. 问题定义与约束

**目标**：给定中心点 `c` 与时长阈值 `T`（300 / 600 / 900 s），求
`A(T) = { p : 从 c 步行到 p 的最短真实耗时 ≤ T }` 的边界多边形。

**三个硬约束（决定了算法形态）**：

| 约束 | 后果 |
| --- | --- |
| 百度地图**不暴露底层路网图** | **无法**直接跑 Dijkstra / A*；只能把 API 当「黑盒测时器」 |
| 批量算路**不返回路线几何** | 边界**必须自行插值重建**，不能靠 polyline 拼接 |
| 配额按**路线数**计费（5,000/日） | 采样点数量是设计的第一变量；一次采样必须**同时服务三个档位** |

## 2. 采样布局（Step 1）

参数取自 `SampleConfig`（`backend/app/core/isochrone.py`，已冻结）：

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| 射线数 `rays` | **36**（10° 间隔） | R<16 时凹地形漏采严重；R>72 收益饱和（见 §3 实测表） |
| 环距 `dr` | **200 m** | 与输出栅格 25 m 匹配；粗环 + 阈值附近加密的组合性价比最高 |
| 外半径 `max_factor` | **1.4** | `r_max = 1.4 × v × T`：阈值**外侧**必须留出粗采样点，否则 IDW 无约束外推 |
| 步行速度 `walk_speed` | **1.25 m/s**（4.5 km/h） | 适老/儿童场景可降到 1.0~1.1 m/s |
| 加密点数 `densify_per_crossing` | **1** | 每个穿越区间插 1 个中点 |
| 栅格分辨率 `grid_res` | **25 m** | 150×150 级别栅格，插值 < 0.3 s |
| IDW 参数 | **k=8, p=2** | Bielecka & Bober 2013 实测 IDW 的 MAPE/MAE 最低 |

**按阈值的具体布局**：

| 阈值 T | `r_max = 1.4 × 1.25 × T` | 环数 `ceil(r_max / 200)` | 粗采样点 `36 × 环数` |
| --- | ---: | ---: | ---: |
| 300 s（5 min） | 525 m | 3 | 108 |
| 600 s（10 min） | 1,050 m | 6 | 216 |
| **900 s（15 min）** | **1,575 m** | **8** | **288** |
| 三档合计（各出一圈） | — | — | 612 |

> **配额复用技巧**：5/10/15 分钟三档的采样点**是同心圆集合**——
> 15 分钟档的 8 环采样**完整包含** 5 分钟档的 3 环与 10 分钟档的 6 环。
> 因此**以 15 分钟档采一次（288 + 加密点），即可同时产出三档等时圈**，成本不随档位数增加。

## 3. 为什么「出多边形用等值线」而不是「把射线交点连起来」

### 3.1 合成场景实测（本机，`bench/benchmark_isochrone.py`）

**场景**：2.4 km × 2.4 km、25 m 栅格、一条**不可穿越的河**（y=400 m，半宽 40 m）+ **唯一桥梁**（半宽 60 m），
制造强凹陷与遮蔽阴影。**真值** = 8 连通栅格 Dijkstra（步行 1.25 m/s）。
真值覆盖 **5225 格 = 3.266 km²**，不可通行 **372 格**。

**实测结果（`backend/bench/result.txt` 原文）**：

| 配置 | 点数 | 请求数 | 极坐标连点 IoU | **IDW + 等值线 IoU** | IDW 面积误差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| R=36 Δr=150 m | 396 | 8 | 0.785 | **0.941** | +0.3% |
| R=36 Δr=200 m + 加密 3 | 396 | 9 | 0.785 | **0.932** | +1.3% |
| R=36 Δr=100 m | 576 | 12 | 0.785 | **0.958** | −1.7% |

原文结论对照（result.txt 末两行）：

> `*` 极坐标连点系统性低估面积（凹角被切掉），IoU 约 0.90~0.93
> `*` IDW+等值线用更少采样达到更高 IoU（约 0.94~0.96）

### 3.2 三条硬结论

1. **极坐标连点的误差由模型偏差主导，而非采样密度**。
   本机这组实测里极坐标法在不同采样密度下的 IoU **恒为 0.785**——提高采样密度**完全不改善**它。
   原因：内接星形多边形会把一切凹角切掉，而凹角恰恰对应河湾、封闭小区这些**最需要被识别的区域**。
   （SOLUTION.md §4.2.2 的另一组实验给出 0.90~0.93 且系统性低估面积 5%~11%，同样是模型偏差主导。）
2. **IDW 场 + 等值线用更少的采样量即可超过极坐标法**（0.958 vs 0.785，且点数只多 45%）。
3. **「粗环 + 阈值附近局部加密」性价比最高**，是本方案的采样策略。

> ⚠️ **必须避免的反例**：只采阈值**内侧**、放弃外侧粗覆盖，会让 IDW 在外侧无约束外推，
> IoU 崩到 **0.62~0.79**、面积误差 **+24%~+59%**。**阈值外侧必须有粗采样点**（`max_factor = 1.4` 就是为此）。

### 3.3 ⚠️ 一处口径不一致（必须如实标注，待验证）

[docs/SOLUTION.md](../SOLUTION.md) §4.2.2 的表格里写着
「**R=36, Δr=200 m + 每射线 3 点加密：432 点 / 9 请求 / IoU 0.944 / 面积误差 +2.7%**」，
而 [backend/bench/result.txt](../../backend/bench/result.txt) 中对应档位是
「R=36 Δr=200 + 加密3：**396 点** / 9 请求 / IoU **0.932** / 面积误差 +1.3%」。

两者**点数与 IoU 均不一致**，推测是「加密点计数口径」不同（每射线计数 vs 每穿越区间计数，
或有效样本数 vs 布点数的差异）。**本设计文档一律以 `bench/result.txt` 的可复现输出为准**；
§4.2.2 中 432 点 / 0.944 的那一档**标注为待验证**，需重跑基准核对后再引用。

**算术自洽性检查（供核对）**：288 个粗采样点若再加「36 射线 × 阈值穿越 4 次 × 3 点」= 432 点，
则与 §4.2.2 的 432 吻合；而每一穿越区间加密 3 点（每射线 1 个穿越区间）⇒ 288 + 108 = 396，与 result.txt 吻合。
**两种口径都可能，必须由重跑基准裁决。**

## 4. 完整算法流水线

```text
输入：中心点 c (BD09)、阈值 T、可选屏障图层
  │
  ├─ Step 1  射线采样布局        ray_layout()          → 36 × 8 = 288 个 (θ, r) 点
  ├─ Step 2  批量测时（含直线距离）measure()            → 9 个请求 / 432 路线；t=0 或缺失 → None
  ├─ Step 3  PAVA 保序回归        monotonicity_stats()  → 单调化 t(r)；输出修正比例
  ├─ Step 4  射线求根            ray_roots()           → 每条射线的 [(r_enter, r_exit), ...]
  ├─ Step 5  阈值附近局部加密     densify()             → +1 点/穿越区间（≈ +108~144 点）
  ├─ Step 6  IDW 重建耗时场       idw_interpolate()     → 25 m 规则栅格（k=8, p=2）+ 中心速度锥
  │          屏障遮蔽            make_barrier_mask()   → 水体/铁路/封闭小区/快速路 → mask
  ├─ Step 7  marching squares     contour_to_polygon()  → contourpy filled() → 填充轮廓
  ├─ Step 8  shapely 拓扑修复     make_valid + unary_union + simplify(0.7 × 25 m)
  └─ Step 9  质量指标            不确定带 / 单调性修正比例 / 请求数与路线数

输出：IsochroneResult（polygon_xy、area_m2、n_samples、n_requests、routes_charged、
      monotonicity_modified_ratio、uncertainty_band_ratio、warnings[]）
```

## 5. 各步骤的设计理由

### Step 3 — PAVA 保序回归（为什么要「修正」实测数据）

百度返回的绑路结果会抖动，偶尔出现 `t(r₂) < t(r₁)`（`r₂ > r₁`）——这是**算法噪声而不是真实可达性**。
直接用会导致射线求根出现**假区间**（凭空多出一段「可达—不可达—又可达」）。

- 用 **PAVA（Pool Adjacent Violators Algorithm）** 把 `t(r)` 单调化；
- 同时把**被修正样本比例**作为**数据质量指标**输出（方案目标 **< 15%**）；
- 实现见 `backend/app/core/monotonic.py`。

### Step 4 — 射线求根，一次拿到「两个边界」

对每条射线，在 `{r_i}` 上找**所有**满足 `t_i ≤ T < t_{i+1}` 的区间（**可能有多个**——正是河/封闭小区场景），
线性插值求根，取**最小根 `r_first`** 与**最大根 `r_last`**：

| 符号 | 语义 | 用途 |
| --- | --- | --- |
| `r_first` | **确定可达边界**（保守下界） | 加密点定位；不确定带**内**边界 |
| `r_last` | **可能可达边界**（乐观上界） | 不确定带**外**边界 |

**这就是赛题痛点「红绿灯、过街天桥、施工围挡极大影响实际可达范围」的正面回答**：
我们不假装边界是一条精确的线，而是把它渲染成**不确定带**（`uncertainty_band_ratio` 量化其面积占比）。

> 注意：射线求根**只用于定位加密点与表达不确定性，不直接出多边形**。

### Step 5 — 阈值附近局部加密

在每个穿越区间内插 1 个中点。理由：IDW 的重建误差与等值线穿过区域的**梯度**强相关，
把预算花在阈值邻域，比均匀加密更划算（§3.1 中 Δr=150 与 Δr=200 两档的差距可佐证）。

### Step 6 — IDW 耗时场（k=8, p=2）+ 三处关键处理

> **文献依据**：Bielecka & Bober 2013（Geodetski vestnik 57(2)）实测 IDW 的 MAPE/MAE 最低；
> 样条（RBF/薄板）会产生「**最不合理的等时圈离岛**」，最近邻误差最大。
> RBF 因全局稠密矩阵 O(N³) 与过冲，本项目**不采用**。

| 处理 | 为什么必须做 |
| --- | --- |
| **屏障遮蔽**（`mask` / 权重置 0） | IDW 会把河对岸、铁路另一侧的低耗时拉过来，在河道上生成**假覆盖（「穿墙」）**。这是本算法最大的失真来源 |
| **中心空洞填充** | `r < Δr` 的圆盘内没有样本，用步行速度锥 `t ≈ r / v` 填充，避免中心出现空洞 |
| **外推保护** | 栅格范围取 `r_max × 1.2`，外圈用最近环样本延拓（§3.2 反例） |

实现要点（`field.py`）：`scipy.spatial.cKDTree` 查询 k 近邻 → `w = 1/d^p` → 加权平均；
与样本点重合时权重取 `1e12` 防止除零；中心锥用 `np.copyto(..., where=(r < radius) & (cone < z))` **只降不升**。

### Step 7 — marching squares（用 contourpy 的 `filled()`）

```python
# backend/app/core/isochrone.py（已冻结）
z_in = np.ma.masked_array(z, mask=mask) if mask is not None else z
cg = contourpy.contour_generator(x=xs, y=ys, z=z_in,
                                 fill_type="ChunkCombinedOffsetOffset")
filled = cg.filled(0.0, target_s)      # 覆盖区 = 0 <= t <= T
```

| 要点 | 说明 |
| --- | --- |
| 用 `filled()` 而不是 `lines()` | 填充轮廓**天然闭合**且自带洞的层级，不需要自己配对环 |
| **实测坑**：contourpy 1.4 通过 `z` 的 **masked array** 表达不可通行区 | 已弃用 `mask=` 关键字参数——按老文档写会直接报错 |
| known limitation | 等值线值**恰等于某格点 z 值**时会输出**重复点** → shapely 判 invalid 或零面积 → **必须 `make_valid`** |
| 备选 skimage | `find_contours` 的轮廓**不保证闭合**（触边界 / mask=False / NaN 会开口），且 `fully_connected` / `positive_orientation` 必须固定，否则同数据两次运行结果不一致。**首选 contourpy**。 |

### Step 8 — shapely 拓扑修复

```python
rings = [Polygon(seg) for seg in ... if len(seg) >= 3]
geom  = unary_union([make_valid(r) for r in rings])
geom  = geom.simplify(0.7 * grid_res, preserve_topology=True)   # 0.7 × 25 m = 17.5 m
```

- `make_valid` **优先**、`buffer(0)` 仅作兜底（`buffer(0)` 在存在洞与细长部件时可能丢部件）；
- 空结果兜底：`shapely.concave_hull(MultiPoint(samples), ratio=0.3, allow_holes=True)`（shapely ≥ 2.1）；
- **保留洞**：封闭小区 / 水域内部不可达区应作为 `Polygon(shell, holes)` **保留**，
  而不是填实——「这个小区内部有条断头河导致绕行」本身就是有价值的体检结论。

## 6. 输出契约与质量指标

### 6.1 输出（对齐 CONTRACT.md §4）

```jsonc
"isochrones": {
  "5":  { "target_seconds": 300, "area_m2": 812345.0, "n_samples": 432,
          "routes_charged": 432, "uncertainty_band_ratio": 0.18,
          "geometry": { "type": "Polygon", "coordinates": [[[121.60,31.20], ...]] } },
  "10": { "...": "同上" },
  "15": { "...": "同上" }
}
```

- **坐标系一律 BD09**；坐标顺序一律 `[lng, lat]`（GeoJSON 标准）；
- 多边形**必须闭合**（首尾点相同）；
- 所有几何为 EPSG 无关的裸坐标（前端 BMapGL 直接接受 BD09 经纬度）。

### 6.2 质量指标（写进体检报告）

| 指标 | 定义 | 目标 | 实测/现状 |
| --- | --- | --- | --- |
| **算法自洽性 IoU** | 极坐标圈 vs IDW 圈（相对真值） | ≥ 0.92 | **[一手实测]** 0.932 / 0.941 / 0.958（`bench/result.txt`） |
| **面积误差** `ε_A` | `(A_ours − A_ref) / A_ref`，**带符号** | |ε_A| ≤ 5% | **[一手实测]** +0.3% / +1.3% / −1.7% |
| **不确定带面积占比** | `(A(r_last) − A(r_first)) / A(r_first)` | 报告实测值 | 由 `IsochroneResult.uncertainty_band_ratio` 输出（**真实社区值待验证**） |
| **样本单调性修正比例** | PAVA 修正的样本占比 | < 15% | 由 `monotonicity_modified_ratio` 输出（**真实社区值待验证**） |
| **屏障遮蔽命中数** | 被 mask 掉的假覆盖格数 | 报告实测值 | **待验证**（需要真实屏障图层） |
| 边界平均偏差 MBD | `mean_{p∈∂A} dist(p, ∂B)`（米） | ≤ 30 m | **待验证**（需按 SOLUTION §11 协议用百度 App 人工实测） |
| 边界 P90 | 沿射线 `e_boundary(θ) = r*_pred − r*_obs` 的 P90 | ≤ 60 m | **待验证** |

> 合成场景实测的边界半径误差：**MAE 29.6 m、p50 4.9 m、p90 20.0 m、max 380 m**（SOLUTION §11）。
> **「均值小、局部大」是常态**，最大值出现在桥梁附近的凹陷处——报告必须给 P90 与 max，只报均值会掩盖最需要解释的失败案例。

## 7. 与权威实现的对齐

**Valhalla 的等时圈**同样是「二维网格 + 从原点扩展 + marching squares 提等值线」，与本方案同构，
差别只在它用自家路网做 Dijkstra、我们用外部 API 采样。
**openrouteservice / r5r(R5)** 则走「网络扩展 + 凹包后处理」路线——它们有路网图，我们没有，故不可照搬。

**射线法本身的依据**：Zhao 2024（IJGI 13(8):288）对比了用第三方算路 API 建等时圈的三种采样法
（行政单元质心 / 规则栅格 / 径向射线），**射线法请求数最少**。

## 8. 已知局限（诚实声明）

| # | 局限 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 1 | 合成场景 IoU **不能当作生产精度承诺** | 单场景、无 API 噪声、未模拟绑路误差与「API 耗时含过街等待」的口径差异 | 必须按 SOLUTION §11 协议做真实社区对比测试（App 人工真值） |
| 2 | 批量算路当前返回 211 | **本机暂时拿不到真实耗时** | 双 provider：`live` / `replay` / `mock`；seed 快照 + 解析模型兜底 |
| 3 | 屏障图层一期靠人工勾绘 | 屏障缺失处仍会「穿墙」 | 一期用样例社区屏障 JSON；二期接百度「水系/绿地」分类 POI + 人工校核 |
| 4 | 解析降级模型未在真实路网标定 | 降级模式精度未知 | 用 `ret_straight_dist=1` 零成本标定（见 05 文档 §7），**待验证** |
| 5 | `bench/result.txt` 与 SOLUTION §4.2.2 的一档数据口径不一致 | 引用时可能出错 | 见 §3.3，**以 result.txt 为准**，差异标注为待验证 |
