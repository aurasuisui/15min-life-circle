## 1. 命题背景与痛点（赛题原文）

近年来，国家大力推行"15 分钟便民生活圈"建设，要求居民在步行 15 分钟范围内能获得基础医疗、教育、购物、养老等服务。然而，目前的社区建设规划多依赖人工普查和静态数据，缺乏对"真实可达性"的动态考量。

**痛点**：道路并非直线，红绿灯、过街天桥、施工围挡等都会极大影响实际步行可达范围。传统评估手段成本高、更新慢，无法精准发现"服务盲区"。亟需一款能够综合利用地图 API（道路路网、实时路况、POI 检索）进行量化分析与自动诊疗的工具。

---

## 2. 命题目标（赛题原文）

参赛团队需基于百度地图提供的地图开放能力（包括但不限于：地理编码/逆地理编码、POI 兴趣点检索、路径规划与距离计算），开发一款 **Web 或小程序应用**。

选手需选定所在城市任意一个社区/街道为样例，输入中心点坐标，系统能自动计算该点基于**真实路网**的"15 分钟步行等时圈"，并统计圈内各类民生设施覆盖情况，输出可视化"体检报告"，自动标注设施匮乏的"灰色区域"。

## 3. 功能需求（FR）

> 每条需求均可独立验收。编号用于第 8 节的评分维度追踪。

### FR-1 中心点输入与地理编码
- 用户可输入**社区/街道名称**或**直接点击地图选点**，获得中心点坐标。
- 系统调用**地理编码**服务把地址解析为坐标；反向需展示该点地址（逆地理编码）。
- 坐标系必须正确：输入 GPS(WGS84) 坐标时需经**坐标转换**为 BD09 后再参与计算。
- **验收**：输入"上海市浦东新区海科路1650号"能定位到正确坐标并在地图上标注。

### FR-2 15 分钟步行等时圈（核心）
- 基于**真实路网**（而非直线距离）计算以中心点为起点、步行 15 分钟可达的范围。
- 必须输出一条**闭合多边形**（等时圈），可在地图上渲染。
- 需支持不同时长档位（如 5 / 10 / 15 分钟）以体现层次。
- **实现路线**（百度地图不暴露底层路网图，无法直接跑 Dijkstra）：
  1. **多环扇形采样**：以中心点为原点，**32 个方位 × 3 个半径 = 96 个采样点**；
  2. 用**步行批量算路**批量获取各采样点的真实步行耗时；
  3. 对耗时场做**等值线提取**（marching squares / contourpy）或 alpha-shape，得到等时圈多边形。
- **降级路线**：配额不足时退化为"直线距离 × 路网绕行系数 + 过街惩罚"的解析模型，并在文档中明确说明。
- **验收**：等时圈边界与百度地图 App 步行导航实测结果的偏差可量化说明。

### FR-3 民生设施覆盖统计
- 对等时圈范围内的多类民生设施做**周边检索**并统计覆盖情况。
- 至少覆盖 8 类：**菜市场 / 药店 / 小学 / 社区医院（卫生服务中心）/ 超市便利店 / 养老设施 / 公交站 / 公园绿地**。
- 每类输出：数量、密度、最近一处的步行耗时、覆盖率评分。
- **必须做多源 POI 数据清洗**（重名、坐标漂移、类型错标、重复 poi）。
- **验收**：给定社区能输出一张分类覆盖统计表。

### FR-4 服务盲区识别
- 识别并在地图上标注设施匮乏的"灰色区域"。
- **明确要求**：能准确识别出**周边 1 公里内没有菜市场、药店或小学**的"服务盲区"点位。
- 盲区判定应基于**步行耗时**而非直线距离。
- **验收**：在样例社区能标出至少若干处盲区，且人工抽查合理。

### FR-5 可视化"体检报告"
- 在地图上准确渲染**等时圈热力图**。
- 提供量化评分展示：**热力图 / 柱状图 / 雷达图**（评分表点名这三类）。
- 报告内容：设施覆盖得分、盲区清单、改善建议。
- **验收**：截图可作为作品介绍文档的核心插图。

### FR-6 产品交互
- 用户可**自定义地图中心点**，操作逻辑清晰。
- 地图交互流畅（缩放/平移无卡顿）。
- 界面美观、响应式。

## 4. 非功能需求（NFR）

### NFR-1 API 配额与限流（**本项目的核心约束**）
个人开发者配额（百度地图开放平台，2025-10 更新）：

| 服务 | 配额/日 | 并发 | 本项目用途 |
| --- | --- | --- | --- |
| 地理编码 | 5,000 | 3 QPS | 地址 → 坐标 |
| **地点检索** | **100** ⚠️ | 3 QPS | POI 周边检索 |
| **步行批量算路** | 5,000 | 3 QPS | 等时圈采样测时 |
| 步行路线规划（轻量） | 5,000 | 3 QPS | 单点兜底 |
| 坐标转换 | 5,000 | 3 QPS | 坐标系互转 |
| 逆地理编码 | 300 | 3 QPS | 坐标 → 地址 |

**用量账本**（已按实际实现校准）：
- 等时圈：**32 方位 × 3 半径 = 96 个采样点** → 拆 2 次请求（单次上限 50）→ **96 配额/圈** → 约 **52 圈/日**
- POI：8 类 × 2 页 = **16 次/社区** → 约 **6 个社区/日**
- **结论：算路配额约有 8 倍冗余，POI 检索 100/日 才是瓶颈。架构必须围绕降低 POI 请求数设计。**

### NFR-2 容错与降级机制（**评分明确考点，30% 权重**）
- POI 检索结果缺失、API 返回异常、触发 QPS 限流时，必须有**异常捕获与兜底**。
- 必须区分**配额耗尽**（快速失败，不重试）与**瞬时失败**（指数退避重试）。
- 令牌桶限流 ≤ 3 QPS（留余量取 2.5）。
- 降级时必须向用户**明确提示数据不完整**，不得静默返回错误结果。

### NFR-3 缓存与离线回放
- POI 与算路结果**落库持久化**，同一社区重复分析命中缓存。
- 提供 **seed 数据集**（预录 POI 快照），使评审方**零配额**即可跑通全流程。

### NFR-4 性能
- 针对大量 POI 使用**批量距离矩阵计算**或并发请求，显著降低耗时。
- 鼓励**空间插值 / 扇形采样**：在不获取底层路网数据的前提下，通过分散点位的 API 测时结果插值推导近似连通区域。

### NFR-5 安全与密钥管理
- 服务端 AK 使用 **SN 签名**，AK/SK 存 `.env`，**仓库只放 `.env.example`**。
- 前端仅使用浏览器端 AK（Referer 白名单）。
- README 必须包含**环境变量配置说明且 AK 已脱敏**。

### NFR-6 开源工程规范
- 标准开源许可证（**Apache 2.0 或 MIT**）。
- 代码结构清晰、模块划分合理、命名规范。
- README 详尽：背景、技术方案、安装部署指南、环境变量说明。
- 配置 **CI/CD**（GitHub Actions 或 Gitee Go）：自动化构建 + 代码格式化检查。
- 提供 **Docker 或一键脚本**，保证评审方快速跑通演示。

## 6. 技术约束与选型建议

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 地图渲染 | **百度地图 JavaScript API GL** + 浏览器端 AK | 命题方指定；支持自定义图层与热力图 |
| 后端 | **Python + FastAPI** | 与另一个赛题的 Python 技术栈复用；地理计算生态好 |
| 等值线提取 | `contourpy` / `scikit-image.measure.find_contours` / `shapely` | 成熟实现，避免手写 marching squares |
| 前端 | Vue 3 + Vite | 轻量、构建快 |
| 缓存 | SQLite（开发）/ Redis（可选） | POI 快照落库 |
| 部署 | Docker Compose | 任务书点名要求"评审方能快速跑通" |

### 数据接口形态（已验证）
```
# 步行批量算路（核心）
GET https://api.map.baidu.com/routematrix/v2/walking
    ?origins=纬度,经度|纬度,经度
    &destinations=纬度,经度|...
    &output=json&ak=AK
# 返回 result 数组，顺序 origin1-dest1, origin1-dest2, ...
# duration.value 单位秒；distance.value 单位米；coord_type 默认 bd09ll

# POI 圆形区域检索
GET https://api.map.baidu.com/place/v2/search
    ?query=菜市场&location=纬度,经度&radius=2000
    &radius_limit=true&page_size=20&page_num=0&output=json&ak=AK
```

### 三个必须注意的坑
1. **批量算路配额按"最终路线数"计**，不是按请求数（2 起点 × 5 终点 = 计 10 次）。
2. **步行一次最多 50 条路线**（起终点之积 ≤ 50；驾车才是 100）。
3. **POI 检索 `radius` 超出城市边界会退化为"全市检索"**，必须显式传 `radius_limit=true`。
4. 步行起终点距离 **> 200KM** 会返回参数错误。
