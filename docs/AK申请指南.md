# 百度地图 AK 申请指南（照这个点就行）

> 整理时间：2026-10-08　|　依据：百度地图开放平台官方文档原文（页面更新时间逐条标注）
> 目标：拿到 **2 个 AK**，跑通 [SOLUTION.md](./SOLUTION.md) 的 D1 闸门。

---

## 0. 一句话结论

**你只申请 2 个应用（AK）：一个「浏览器端」，一个「服务端」。** 再加一次「开发者认证」。

| # | 应用名称（建议） | 应用类型 | 校验方式 | 用途 | 填到 .env |
| --- | --- | --- | --- | --- | --- |
| 1 | `15min-life-circle-web` | **浏览器端** | Referer 白名单 | 前端地图渲染（JSAPI） | `VITE_BAIDU_MAP_BROWSER_AK` |
| 2 | `15min-life-circle-server` | **服务端** | **SN 签名** | 全部数据能力（地理编码/POI/算路/坐标转换） | `BAIDU_MAP_SERVER_AK` + `BAIDU_MAP_SERVER_SK` |

> ⚠️ **AK 按「调用端」区分，勾选的服务不通用。** 浏览器端 AK 调服务端接口会返回 `status=203 APP类型错误`；服务端 AK 拿去前端渲染会失败。

## 1. 前置：注册 + 开发者认证

官方《地点检索 · 使用准备》（页面更新 2026/03/21）原文四步：

> 1. **申请百度账号** —— 录入个人姓名、电话、邮箱
> 2. **成为开发者** —— 选择个人/企业认证，按系统提示完成开发者认证
> 3. **获取服务密钥（AK）** —— 为 AK 命名，选取 AK 中需包括的服务，同时选择 AK 的校验方式
> 4. **发送请求使用服务**

**入口**：`https://lbsyun.baidu.com/` → 右上角「登录」/「注册」→ 登录后进入 **控制台**。
认证入口在控制台里（`https://lbsyun.baidu.com/apiconsole/auth`）。

**认证类型怎么选**

| 类型 | 适用 | 大致材料 | 我们的建议 |
| --- | --- | --- | --- |
| 个人开发者 | 我们就是 | 姓名、身份证号、手机号（可能需人脸核身） | ✅ **选这个**，最快 |
| 企业开发者 | 公司主体参赛 | 营业执照、对公信息 | 除非你们以公司名义报名，否则不需要 |

> 📌 **关于「认证 vs 配额」的准确说法**：官方《开发者权益》页（2025-10 更新）**只有 3 列**——个人开发者 / 企业开发者（试用版）/ 企业开发者（授权版），**没有「未认证 / 已认证」这个维度**。但接口状态码 `4 Quota Failure` 的文案写着「请优先进行**开发者认证**」，说明**认证是申请提额的前置动作**，不是配额档位。
> → **务实做法：先注册能建 AK 就先建、先把活干起来；同时把认证提交了，以免将来提额被卡。**

## 2. 应用 #1：浏览器端 AK（前端地图渲染）

依据：官方《JSAPI 4.0 · 开发前准备》（更新 2026/07/17）与《JSAPI GL · 账号和获取密钥》（更新 2026/07/27）。

**步骤**

1. 登录 `https://lbsyun.baidu.com/` → 点 **控制台**（右上角）
2. 左侧栏 → **应用管理** → **我的应用**
3. 点 **创建应用**
4. 填写：

   | 字段 | 填什么 | 说明 |
   | --- | --- | --- |
   | 应用名称 | `15min-life-circle-web` | 任意，建议带项目名 |
   | **应用类型** | **浏览器端** | 🔴 **这一步最重要**，官方原文：「JS API 只支持浏览器端 AK 进行请求与访问」 |
   | Referer 白名单 | 开发期填 `*`；或更严格：`localhost:5173*` + `127.0.0.1:5173*` | 官方原文：「为了防止您的 AK 被盗用，请您务必配置 refer 白名单」。**上线前必须改成实际域名** |

5. 提交 → 在应用列表里**复制 AK** → 填进 `.env` 的 `VITE_BAIDU_MAP_BROWSER_AK`

**这个 AK 需要勾选什么服务？** 只勾 **JavaScript API GL**（或 JSAPI 4.0 对应的地图服务）。
**不要**勾 JS API 地点检索 / 路线规划——官方权益表里 **JS API 地点检索个人同样只有 100/日**，前端直调绕不开瓶颈，我们全部走后端。

**上线加固（加分项，对应「AK 需脱敏」评分点）**：官方推荐用 Nginx 反向代理把 AK 藏在服务端 —— 前端在加载 SDK 前定义 `window._BMapSecurityConfig = { serviceHost: '<你的域名>/_BMapService/' }`，SDK 从代理地址加载且**不传 ak**。详见官方《使用代理保护 AK》。

## 3. 应用 #2：服务端 AK（所有数据能力）

**步骤**

1. 同样在 **应用管理 → 我的应用 → 创建应用**
2. 填写：

   | 字段 | 填什么 | 说明 |
   | --- | --- | --- |
   | 应用名称 | `15min-life-circle-server` | |
   | **应用类型** | **服务端** | |
   | **校验方式** | **SN 签名**（不要选 IP 白名单） | 🔴 见下方说明 |
   | IP 白名单 | 选 SN 后不需要填 | |

3. **勾选服务**（最关键的一步，勾漏了要回来改 AK）
4. 提交 → 复制 **AK** 和 **SK（Security Key）** → 填进 `.env`

### 3.1 为什么必须选「SN 签名」而不是「IP 白名单」

| | IP 白名单 | **SN 签名**（选它） |
| --- | --- | --- |
| 绑定 | 绑调用方公网 IP | 不绑 IP |
| 评审方换台机器跑 | ❌ 直接失败（`status=210 APP IP校验失败`） | ✅ 只要 `.env` 填了 AK/SK 就能跑 |
| 密钥暴露面 | AK 明文在 `.env` | AK 明文在 `.env`，SK 仅在服务端参与签名 |
| 评分收益 | 无 | 直接对应「API 深度调用与工程优化」的工程能力展示 |

> 选 SN 后会生成 **SK**。**SK 绝不能进 Git 仓库**（`.gitignore` 已覆盖 `.env`，仓库只放 `.env.example`）。

### 3.2 服务勾选清单 🔴 照着勾

依据：官方《开发者权益》（2025-10 更新） + 本项目 [SOLUTION.md](./SOLUTION.md) §2.1 配额账本。

**必勾 5 项**

| 勾选 | 服务名（控制台里的叫法） | 个人配额/日 | 本项目用途 |
| --- | --- | --- | --- |
| ✅ | **地理编码** | 5,000 | 「上海市浦东新区海科路1650号」→ 坐标 |
| ✅ | **地点检索** | **100** ⚠️ | POI 周边/多边形检索（**瓶颈**） |
| ✅ | **批量算路** | 5,000 | **等时圈核心**：一次 1×50 采样测时 |
| ✅ | **步行路线规划（轻量）** | 5,000 | 单点兜底 + 路径回显 |
| ✅ | **坐标转换** | 5,000 | WGS84/GCJ02 ↔ BD09 |

**建议加勾 3 项**

| 勾选 | 服务 | 配额/日 | 用途 |
| --- | --- | --- | --- |
| ⭕ | **逆地理编码** | 300 | 报告里给社区/盲区命名（缓存着用，**建议 ≤200 次/日**） |
| ⭕ | **行政区划查询** | 5,000 | 取市/区边界与 adcode（**注意：官方明确不支持乡镇/街道边界**） |
| ⭕ | **静态图** | 5,000 | 体检报告配图（可选） |

**不要勾**

| ❌ | 原因 |
| --- | --- |
| 实时路况查询 | 步行不受车行路况影响，纯浪费 |
| 多维检索 / 深度检索 | 配额只有 **10/日**，不可依赖 |
| 摩托车路线规划 / 批量算路 | 配额 100/日，用不上 |
| 全球逆地理编码 / 境外服务 | 用不上，且多需商用授权 |
| 鹰眼轨迹、静态图（如不用） | 无关 |

> 📌 **勾漏了的后果**：接口会返回 `status=240 APP 服务被禁用`。这时需要回控制台为该 AK 补勾服务（有时需要重新生成 AK）。

## 4. 填 `.env`

```bash
cp .env.example .env
```

然后编辑 `.env`：

```ini
VITE_BAIDU_MAP_BROWSER_AK=应用#1 的 AK
BAIDU_MAP_SERVER_AK=应用#2 的 AK
BAIDU_MAP_SERVER_SK=应用#2 的 SK
```

其余配额参数保持默认（`API_QPS_LIMIT=2.5` 是刻意留 17% 余量，别调到 3.0）。

## 5. 验证：跑 `scripts/check_ak.py`

仓库里已经写好一个**零第三方依赖**的验证脚本（只用 Python 标准库）：

```bash
python scripts/check_ak.py
```

它会依次做 6 件事，并把**配额消耗**和**每步结果**打出来：

| # | 检查项 | 消耗配额 | 目的 |
| --- | --- | --- | --- |
| 0 | SN 签名自检（官方测试向量） | 0 | **不需要 AK** 就能验证签名实现是否正确 |
| 1 | 地理编码「上海市浦东新区海科路1650号」 | 1 | 对应任务书 FR-1 验收原文 |
| 2 | 坐标转换（WGS84 → BD09） | 1 | 验证坐标系链路 |
| 3 | 步行批量算路 1×2 | 2 | 验证等时圈核心接口 |
| 4 | 地点检索 · 单关键字 | 1 | 基线 |
| 5 | 地点检索 · **多关键字并集** | 1 或 3（**待实测**） | 🚦 **D1 闸门 G1**：确认多关键字是否按请求计费 |

第 5 步跑完，**去控制台「用量统计 / 我的额度」看地点检索当天消耗增加了 1 还是 3** —— 这个数字决定 [SOLUTION.md](./SOLUTION.md) §2.2 的 POI 策略，是整个架构的第一个分叉点。

## 6. 六个必知坑（都是一手文档原文或本机实测）

1. **`radius` 超界会退化成「整城检索」** —— 官方原文：「当半径过大，超过中心点所在城市边界时，会变为城市范围检索」。开大半径**不会**拿到更多，只会拿到一城脏数据。
2. **`total` 不可信** —— 需传 `page_num` 才出现，且官方硬性封顶 **150**。任何「用 total 数设施」的做法都是错的。
3. **v2 的 `bounds` 多边形检索是高级权限**（需商用授权），别依赖；改用 `place/v3/polygon`（**待 D1 实测是否对个人开放**）。
4. **`tag` 不是过滤器**，只是「分类偏好」。要严格按类型检索必须用 `query`（v3 里 `type` 才是筛选）。
5. **不同 API 错误码语义不一致**（本机实测）：非法 AK 时 `place/v2/search` 返回 `status=200`，而 `routematrix/v2/walking` 返回 `status=2`。容错层必须按服务分别建表。
6. **SN 签名要「编码两次」** —— 先对每个 value 编码拼串，再对 `路径 + "?" + 参数串 + sk` **整串再编码一次**，最后 MD5 取 32 位小写。漏掉第二次编码会稳定报 `status=211`。
